# Asset Control

Electronics asset control for a workplace. An administrator creates security officer accounts. Officers register employees and their devices, print a QR label for each device, and verify ownership at checkpoints by scanning the QR code or typing the asset ID or employee ID.

## Run it

Requires Node.js 20 or newer.

```
npm install
npm start
```

The React interface is compiled locally during `npm start`. To build it separately, run `npm run build`.

Open http://localhost:3000 and sign in with the first administrator:

- Username: `admin`
- Password: `ChangeMe123!`

Change the password straight away (Change password, top right). To choose your own first account, set `ADMIN_USER` and `ADMIN_PASSWORD` before the first start.

## Reset an administrator password

If you lose access, run `npm run reset-admin-password` from the project folder in an interactive terminal. Select the administrator account and enter a new password of at least 12 characters twice; terminal input is hidden. The command updates only that account and creates a timestamped SQLite backup before making the change. Keep the backup private and remove it securely when it is no longer needed. Do not delete `assets.db` or use `ADMIN_PASSWORD` to try to reset an existing account.

## How it works

1. **Administrator** creates security officers (Security officers tab). Can disable an officer or reset a password. Has read-only views of employees, devices and activity.
2. **Security officer** registers employees, then registers a device and picks its owner. The system assigns an asset ID (AST-000001, ...) and shows a QR label to print.
3. **Verification** (Verify tab): scan the QR code with the camera, or type the asset ID or employee ID. The system fetches the registered owner from the database. The officer compares it with the person present and records Owner matches or Owner does not match.
4. Every verification is saved in the Activity log with the officer, time and method.

The QR code holds only a random token, never personal data. Details are looked up behind login.

## Going live

- Serve it over **HTTPS**. Phone cameras only allow QR scanning on HTTPS or localhost.
- Set `NODE_ENV=production` and a fixed `SESSION_SECRET` (a long random string). Run behind a proxy such as Nginx.
- Back up `assets.db` regularly.
- Sessions are kept in memory, so officers sign in again after a restart. For many users, switch to a persistent session store.

## Files

- `server.js`: API, sign-in, database tables, QR generation
- `src/app.jsx`: React interface and application workflows
- `public/index.html`: app shell and styles
- `public/app.js`: bundled React client, generated by the build command
- `assets.db`: created on first run
